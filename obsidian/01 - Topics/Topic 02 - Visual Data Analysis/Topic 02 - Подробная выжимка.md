# Topic 02 — Подробная выжимка

## 1. Зачем вообще нужна визуализация

В ML визуализация — часть исследования данных. Она помогает быстрее увидеть структуру, которую сложно заметить в таблице из тысяч строк: форму распределения, выбросы, дисбаланс классов, различия между группами, взаимосвязи и подозрительные измерения.

Правильный график начинается не с библиотеки, а с вопроса.

Мой базовый шаблон:

```text
1. Что я хочу узнать?
2. Какие типы признаков участвуют?
3. Какой график отвечает на этот вопрос?
4. Что именно я вижу?
5. Могу ли я подтвердить это числом?
6. Какой вывод допустим, а какой уже слишком сильный?
```

## 2. Один числовой признак

### Histogram

Подходит для первого просмотра распределения. Показывает частоту/плотность значений в интервалах.

Ищу:
- асимметрию;
- длинные хвосты;
- несколько мод;
- необычные диапазоны;
- возможные ошибки.

### KDE

Сглаженная оценка плотности. Удобна для сравнения формы распределений, особенно нескольких групп, но зависит от параметров сглаживания.

### Boxplot

Компактно показывает медиану, квартильный диапазон и потенциальные выбросы.

Формально:

```text
IQR = Q3 - Q1
нижняя граница ≈ Q1 - 1.5 × IQR
верхняя граница ≈ Q3 + 1.5 × IQR
```

Точка за границей не обязательно ошибка.

### Violinplot

Полезен, когда хочу одновременно видеть различия между группами и форму распределения внутри каждой группы.

## 3. Категориальные признаки

### Countplot

Использую для количества объектов по категориям.

Но если размеры групп различаются, raw counts могут вводить в заблуждение. Тогда считаю доли:

```python
pd.crosstab(df['category'], df['target'], normalize='index')
```

Это ключевой приём в telecom churn: важно не сколько churn-клиентов имеют international plan, а **какая доля клиентов уходит внутри каждой группы plan**.

## 4. Сравнение числового признака между группами

Примеры вопросов:
- отличаются ли churned клиенты по дневным минутам;
- отличается ли BMI у людей с `cardio=0` и `cardio=1`;
- различается ли рост между кодами gender.

Полезны:
- boxplot;
- violinplot;
- histplot с `hue`;
- KDE по группам.

После графика проверяю:

```python
df.groupby('group')['feature'].agg(['mean', 'median', 'std', 'count'])
```

## 5. Два числовых признака

### Scatterplot

Использую, чтобы увидеть:
- линейную связь;
- нелинейную структуру;
- кластеры;
- гетероскедастичность;
- выбросы;
- различия target-классов через `hue`.

В telecom dataset пары `minutes ↔ charge` почти детерминированы: тарифная стоимость вычисляется из продолжительности. Это пример высокой корреляции из-за смысла признаков, а не «интересной закономерности».

## 6. Корреляции

### Pearson

Ищет линейную связь.

Хороший сценарий:

```text
heatmap → заметил сильную пару → scatterplot → понял смысл → решил, что делать дальше
```

### Spearman

Работает с рангами и полезен для монотонных отношений. Может показать сильную связь там, где зависимость не строго линейна.

### Корреляция ≠ причинность

Высокая корреляция может возникать из-за:
- прямой формулы между признаками;
- общего третьего фактора;
- процесса измерения;
- реальной физической/бизнес-связи;
- ошибок данных.

## 7. Visual EDA как связное исследование

EDA не должен выглядеть так:

```text
histplot
boxplot
heatmap
scatterplot
```

Правильнее:

```text
какой базовый rate target?
↓
какие признаки логично сравнить с target?
↓
есть ли различия распределений?
↓
подтверждаются ли они агрегатами?
↓
есть ли дублирующие признаки?
↓
какие гипотезы несу в моделирование?
```

## 8. Telecom churn — основные аналитические идеи

### Target balance

Сначала смотрю долю churn. Класс оттока является меньшинством, значит дальше нельзя бездумно сравнивать только absolute counts.

### International plan

Визуально и через нормированный crosstab проверяю, отличается ли churn rate у клиентов с международным планом.

Вывод формулирую как ассоциацию: признак может быть полезен для модели. Нельзя утверждать, что сам plan является причиной ухода.

### Customer service calls

Смотрю churn rate по количеству обращений. Здесь возможна threshold-like зависимость: после нескольких звонков доля churn может резко вырасти.

Обязательно смотрю `count` каждой группы, потому что редкие экстремальные значения дают нестабильные доли.

### Minutes и charges

Почти полная зависимость означает redundancy. Позже это важно для интерпретации моделей и отбора признаков.

## 9. Cardiovascular assignment — главные уроки

### Не угадывать encoding

`gender=1/2` не подписан. Сначала анализирую рост по коду и только затем формулирую предположение о соответствии полу.

### Age хранится в днях

Перед интерпретацией проверяю масштаб и описание данных. Преобразую в годы/месяцы.

### BMI

```python
BMI = weight_kg / height_m ** 2
```

Это derived feature: он объединяет две колонки в более интерпретируемое отношение.

### Cleaning

В задании удаляются:
- `ap_lo > ap_hi`;
- крайние 2.5% и 97.5% по росту;
- крайние 2.5% и 97.5% по весу.

После фильтрации всегда считаю, сколько процентов данных потерял.

### Pearson и Spearman heatmaps

Строю обе матрицы и сравниваю сильные пары. Важно не просто назвать максимальный коэффициент, а объяснить возможную природу связи.

## 10. Как показывать ход анализа в ноутбуке

Вместо длинного внутреннего монолога фиксирую короткие проверяемые блоки:

> **Question:** что хочу узнать.
>
> **Hypothesis:** какое различие ожидаю и почему.
>
> **Why this chart:** почему этот тип графика подходит.
>
> **Check:** какой числовой расчёт подтверждает/опровергает визуальное впечатление.
>
> **Takeaway:** что можно утверждать.
>
> **Caution:** чего этот анализ не доказывает.

Такой формат полезен для повторения, портфолио и защиты решения.

## 11. Мини-шпаргалка

| Ситуация | Инструмент |
|---|---|
| распределение числа | `sns.histplot(..., kde=True)` |
| выбросы | `sns.boxplot()` |
| форма по группам | `sns.violinplot()` |
| категории | `sns.countplot()` |
| доли target по категории | `pd.crosstab(..., normalize='index')` |
| два числа | `sns.scatterplot()` |
| линейные связи | `df.corr(method='pearson')` |
| ранговые связи | `df.corr(method='spearman')` |
| матрица связей | `sns.heatmap()` |

## 12. Что должно перейти в следующие темы

Topic 02 не выбирает финальную модель. Он формирует гипотезы:
- какие признаки могут быть сильными;
- где есть threshold effects;
- где данные грязные;
- какие признаки дублируются;
- где есть class imbalance;
- какие преобразования могут быть полезны.

Дальше эти идеи должны проверяться на отложенных данных, а не приниматься на веру только потому, что график выглядит убедительно.
