# Topic 05 — Bagging и Random Forest: подробная выжимка

[[ML Course]] · [[Topic 04 - Подробная выжимка]]

## 1. Главная идея

Одно глубокое дерево очень гибкое, но нестабильное: чуть изменились данные — дерево может построиться совсем иначе. Topic 05 отвечает на вопрос: **можно ли взять много нестабильных моделей и получить из них стабильную?**

Да. Если ошибки отдельных моделей отличаются, их усреднение уменьшает случайную составляющую ошибки.

```text
одно дерево → высокая variance
много разных деревьев + averaging → variance ниже
```

## 2. Bias и variance простыми словами

- **Bias** — модель слишком простая и систематически не улавливает закономерность.
- **Variance** — модель слишком сильно зависит от конкретной обучающей выборки.

Глубокое дерево обычно имеет небольшой bias, но большую variance.

Bagging в первую очередь борется именно с variance.

## 3. Bootstrap

Чтобы деревья получились разными, каждое обучают на своей bootstrap-выборке.

Bootstrap — выбор `n` объектов из исходных `n` **с возвращением**.

Поэтому некоторые строки попадут несколько раз, а некоторые не попадут вообще.

```python
sample = df.sample(n=len(df), replace=True, random_state=42)
```

## 4. Bagging

Схема:

```text
train
 ├─ bootstrap #1 → model #1 ┐
 ├─ bootstrap #2 → model #2 ├→ усреднение / голосование
 ├─ bootstrap #3 → model #3 ┤
 └─ ...                     ┘
```

Для классификации модели голосуют или усредняют вероятности. Для регрессии — усредняют прогнозы.

В sklearn:

```python
from sklearn.ensemble import BaggingClassifier
from sklearn.tree import DecisionTreeClassifier

model = BaggingClassifier(
    estimator=DecisionTreeClassifier(),
    n_estimators=200,
    random_state=42,
)
```

## 5. Почему простого bagging недостаточно

Если в данных есть один очень сильный признак, разные деревья могут постоянно выбирать его первым. Тогда деревья становятся похожими, а их ошибки — коррелированными.

Если все модели ошибаются одинаково, averaging помогает слабее.

Отсюда идея Random Forest: **декоррелировать деревья ещё сильнее**.

## 6. Random Forest

Random Forest сочетает:

1. bootstrap объектов;
2. случайное подмножество признаков при каждом split;
3. глубокие decision trees;
4. усреднение результатов.

```python
from sklearn.ensemble import RandomForestClassifier

rf = RandomForestClassifier(
    n_estimators=300,
    max_features="sqrt",
    random_state=42,
    n_jobs=-1,
)
```

`max_features` не означает, что дерево вообще увидит только эти признаки. Новое случайное подмножество выбирается **в каждом узле**.

## 7. Почему forest обычно лучше одного дерева

Отдельное дерево может случайно построить неудачные splits. В лесу такие ошибки частично компенсируются другими деревьями.

Полезная интуиция:

```text
качество ensemble зависит от:
1. качества отдельных моделей
2. различия их ошибок
```

Нам нужны модели достаточно хорошие, но не идентичные.

## 8. Основные параметры

### `n_estimators`

Число деревьев.

Больше деревьев обычно делает результат стабильнее, но увеличивает время и память. После некоторого значения качество почти перестаёт меняться.

### `max_depth`

Ограничивает глубину отдельных деревьев. В forest глубокие деревья допустимее, чем одиночное дерево, потому что averaging уменьшает variance.

### `max_features`

Сколько признаков рассматривать при split. Меньше → деревья разнообразнее, но отдельное дерево может стать слабее.

### `min_samples_leaf`

Увеличение делает деревья более гладкими и может помочь против переобучения.

### `class_weight`

Может учитывать дисбаланс классов, но не заменяет правильную метрику и анализ ошибок.

## 9. Out-of-Bag (OOB)

В bootstrap конкретный объект примерно в 36.8% случаев не попадает в выборку отдельного дерева.

Эти объекты называются out-of-bag для данного дерева.

Можно оценивать объект только теми деревьями, которые его не видели:

```python
RandomForestClassifier(
    n_estimators=300,
    oob_score=True,
    bootstrap=True,
)
```

OOB — удобная внутренняя оценка, но для серьёзного model comparison я всё равно предпочитаю заранее выбранную CV-схему.

## 10. Feature importance: осторожно

### Impurity importance

```python
rf.feature_importances_
```

Считает, насколько splits по признаку суммарно уменьшали impurity.

Плюс — быстро. Минусы — может отдавать предпочтение непрерывным/high-cardinality признакам и распределять важность странно между коррелированными признаками.

### Permutation importance

Идея: перемешать один признак на validation data и посмотреть, насколько ухудшилось качество.

```python
from sklearn.inspection import permutation_importance

result = permutation_importance(
    rf,
    X_valid,
    y_valid,
    scoring="roc_auc",
    random_state=42,
)
```

Если после разрушения признака score сильно падает, модель реально на него опиралась.

## 11. Почему importance ≠ причинность

Если `income` важен для прогноза дефолта, это не означает:

> изменение income обязательно причинно изменит дефолт.

Importance говорит о predictive dependency модели на данных.

Также два почти одинаковых признака могут делить importance между собой: каждый по отдельности кажется менее важным, хотя информация группы признаков очень важна.

## 12. Random Forest и scaling

Для обычных деревьев scaling практически не нужен.

Почему? Split вида:

```text
income <= 100000
```

после линейного scaling станет другим числом, но порядок объектов сохранится.

Это сильный контраст с k-NN и линейными моделями с регуляризацией.

## 13. Что смотреть при обучении

Не только одну финальную цифру.

Я проверяю:

- CV mean;
- CV std;
- train vs validation;
- стабилизировалось ли качество по `n_estimators`;
- confusion matrix / нужную бизнес-метрику;
- permutation importance;
- latency и размер модели.

Большой forest может дать +0.001 к score, но стоить в 5 раз дороже. Это не всегда разумный обмен.

## 14. Когда Random Forest особенно удобен

- табличные данные;
- нелинейные зависимости;
- interactions;
- нужен сильный baseline почти без сложной подготовки;
- есть смесь признаков после корректного encoding;
- важна устойчивость по сравнению с одним деревом.

## 15. Ограничения

- модель может быть тяжёлой;
- хуже интерпретируется, чем одно дерево/линейная модель;
- не экстраполирует линейный trend за диапазон train как линейная регрессия;
- high-cardinality категории всё равно требуют грамотной обработки;
- feature importance легко переинтерпретировать.

## 16. Bagging vs Boosting

Важно не путать с Topic 10.

```text
Bagging / Random Forest:
модели строятся независимо → затем усредняются
главная цель: снизить variance

Boosting:
модели строятся последовательно
каждая следующая исправляет текущие ошибки ансамбля
```

## 17. Типичные ошибки

- сравнивать forest с деревом на разных splits;
- считать `feature_importances_` абсолютной истиной;
- подбирать параметры по test set;
- увеличивать `n_estimators` бесконечно в надежде на бесконечный рост score;
- забывать о class imbalance;
- игнорировать стоимость inference;
- говорить «признак влияет», когда измерена только predictive importance.

## 18. Как я решаю новую задачу

1. Строю простой baseline.
2. Обучаю одно дерево и смотрю его variance/overfit.
3. Обучаю Random Forest на той же CV-схеме.
4. Сравниваю mean и std.
5. Проверяю, стабилизировался ли результат по числу деревьев.
6. Настраиваю `max_features`, depth/leaf только по CV.
7. Анализирую ошибки.
8. Смотрю permutation importance на held-out данных.
9. Проверяю latency/размер.
10. Только после этого делаю финальную оценку на test.

RandomForestClassifier(
