# Topic 03 — Decision Trees и k-NN: подробная выжимка

[[ML Course]] · [[Topic 02 - Подробная выжимка]]

## 1. Что я должен понять после темы

До этой темы я в основном изучал данные. Теперь появляется классическая задача машинного обучения: есть признаки `X`, известный ответ `y`, и нужно научиться предсказывать `y` для новых объектов.

Главная идея темы не в том, чтобы запомнить два алгоритма. Нужно понять **как честно сравнивать модели** и почему одна и та же модель может быть отличной на train и плохой на новых данных.

Базовый процесс:

```text
задача → target → метрика → train/validation/test → baseline
       → обучение → проверка → настройка сложности → финальная оценка
```

## 2. Сначала постановка задачи

Пусть есть клиенты и признак `churn`:

```python
X = df.drop(columns="churn")
y = df["churn"]
```

`X` — то, что модель знает в момент прогноза. `y` — правильный ответ, который модель должна научиться восстанавливать.

Первый вопрос всегда не «какую модель взять?», а:

- что является одним объектом;
- что именно предсказываю;
- какие признаки реально доступны;
- как измеряется ошибка;
- одинаково ли плохи false positive и false negative.

## 3. Зачем делить данные

Если обучить модель и проверить её на тех же объектах, я измерю способность запоминать, а не обобщать.

Минимальная схема:

```python
from sklearn.model_selection import train_test_split

X_train, X_test, y_train, y_test = train_test_split(
    X, y,
    test_size=0.2,
    stratify=y,
    random_state=42,
)
```

`stratify=y` сохраняет примерно одинаковую долю классов.

Но test set — не место для постоянного перебора параметров. Если я 50 раз посмотрел test score и выбрал лучший вариант, test фактически стал частью обучения.

Правильнее:

```text
train → обучение
CV / validation → выбор модели и гиперпараметров
test → один финальный экзамен
```

## 4. Baseline

До сложной модели нужен простой ориентир.

Например, классификатор, всегда выбирающий самый частый класс:

```python
from sklearn.dummy import DummyClassifier

baseline = DummyClassifier(strategy="most_frequent")
baseline.fit(X_train, y_train)
```

Если сложная модель почти не лучше baseline, красивое название алгоритма ничего не значит.

## 5. Decision Tree — интуиция

Дерево строит последовательность вопросов:

```text
age <= 35?
├── да → income <= 50k?
│        ├── да → class 0
│        └── нет → class 1
└── нет → ...
```

Каждый узел выбирает признак и порог, которые делают дочерние группы более «чистыми» по target.

В классификации часто используются Gini impurity или entropy.

### Gini

Если в узле доли классов `p1, p2, ...`:

```text
Gini = 1 - Σ p_k²
```

Если все объекты одного класса, impurity = 0. Чем сильнее смешаны классы, тем impurity выше.

Дерево ищет split, который сильнее уменьшает impurity.

## 6. Почему дерево легко переобучается

Если не ограничивать дерево, оно может создавать всё более специфичные правила вплоть до отдельных наблюдений.

Получается:

```text
train accuracy ≈ 1.00
validation accuracy заметно ниже
```

Это классический high variance.

Основные ограничения:

```python
DecisionTreeClassifier(
    max_depth=5,
    min_samples_split=10,
    min_samples_leaf=5,
    random_state=42,
)
```

- `max_depth` — максимальная глубина;
- `min_samples_split` — минимум объектов для дальнейшего деления;
- `min_samples_leaf` — минимум объектов в листе.

Полезная мысль: **глубже ≠ лучше**. Глубина увеличивает способность модели описывать train, но не гарантирует лучшего generalization.

## 7. Как увидеть переобучение дерева

Можно сравнить train и CV score для разных глубин:

```python
for depth in range(1, 15):
    model = DecisionTreeClassifier(max_depth=depth, random_state=42)
    ...
```

Обычно картина такая:

```text
маленькая depth → train низкий, validation низкий → underfit
средняя depth   → validation максимум
большая depth  → train растёт, validation перестаёт расти/падает → overfit
```

Это один из самых наглядных примеров bias–variance trade-off.

## 8. Плюсы и минусы дерева

Плюсы:

- легко объяснить человеку;
- умеет нелинейные зависимости;
- автоматически строит interactions;
- scaling обычно не нужен;
- подходит и для классификации, и для регрессии.

Минусы:

- нестабильно: небольшое изменение данных может поменять структуру;
- легко переобучается;
- кусочно-постоянный прогноз;
- одно дерево часто слабее ансамблей.

## 9. k-NN — совсем другая логика

k-NN почти ничего не «учит» заранее. Для нового объекта он ищет ближайшие объекты train и смотрит на их ответы.

Например, `k=5`:

```text
новый объект
   ↓
5 ближайших соседей
[1, 1, 0, 1, 0]
   ↓
большинство = 1
```

В sklearn:

```python
from sklearn.neighbors import KNeighborsClassifier

knn = KNeighborsClassifier(n_neighbors=5)
knn.fit(X_train, y_train)
```

## 10. Почему scaling для k-NN критичен

Расстояние зависит от масштаба.

Пусть:

```text
age:    18 ... 80
income: 20 000 ... 500 000
```

Без scaling разница в income практически полностью определит евклидово расстояние, даже если возраст очень важен.

Поэтому:

```python
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler

knn = Pipeline([
    ("scale", StandardScaler()),
    ("model", KNeighborsClassifier(n_neighbors=5)),
])
```

Почему scaler внутри Pipeline? Потому что его `mean` и `std` должны вычисляться только на train части каждого fold.

## 11. Что делает параметр k

Маленькое `k`:

```text
+ ловит локальную структуру
- очень чувствительно к шуму
- высокая variance
```

Большое `k`:

```text
+ прогноз стабильнее
- граница становится слишком гладкой
- растёт bias
```

То есть `k` — ещё один регулятор сложности.

## 12. Curse of dimensionality

При большом числе признаков понятие «близкий сосед» становится менее полезным: расстояния между объектами начинают становиться похожими.

Поэтому k-NN часто ухудшается при:

- большом числе шумовых признаков;
- sparse one-hot пространстве;
- очень высокой размерности.

Это важный мост к Topic 06–07, где появятся feature selection и dimensionality reduction.

## 13. Метрики классификации

### Accuracy

```text
правильные прогнозы / все прогнозы
```

Хороша, если классы примерно сбалансированы и ошибки имеют близкую цену.

### Precision

Из всех объектов, которым модель сказала «1», сколько действительно `1`?

```text
precision = TP / (TP + FP)
```

### Recall

Из всех настоящих `1` сколько модель нашла?

```text
recall = TP / (TP + FN)
```

### F1

Гармоническое среднее precision и recall.

### ROC-AUC

Показывает способность модели ранжировать positive выше negative по разным thresholds.

Важно: **метрика выбирается из смысла задачи, а не потому что её удобно вызвать в sklearn.**

## 14. Confusion matrix

```text
             predicted 0   predicted 1
actual 0         TN            FP
actual 1         FN            TP
```

Она помогает увидеть тип ошибки, который скрывает одна итоговая цифра.

Например, медицинская модель может иметь высокую accuracy, но пропускать опасно много больных — тогда recall критичнее.

## 15. Cross-validation

Одна validation выборка может случайно оказаться удачной или неудачной.

CV несколько раз меняет validation fold:

```python
from sklearn.model_selection import cross_val_score

scores = cross_val_score(model, X, y, cv=5, scoring="accuracy")
print(scores.mean(), scores.std())
```

Смотрю не только mean, но и разброс score.

## 16. Подбор гиперпараметров

```python
from sklearn.model_selection import GridSearchCV

params = {
    "max_depth": [3, 5, 7, 10],
    "min_samples_leaf": [1, 5, 10],
}

search = GridSearchCV(
    DecisionTreeClassifier(random_state=42),
    params,
    cv=5,
    scoring="accuracy",
)
```

Для Pipeline имя параметра выглядит, например:

```python
{"model__n_neighbors": [3, 5, 9, 15]}
```

## 17. Decision Tree vs k-NN

| Свойство | Decision Tree | k-NN |
|---|---|---|
| обучение | строит правила | почти запоминает данные |
| prediction | быстро | может быть дорого |
| scaling | обычно не нужен | критически важен |
| нелинейность | да | да |
| интерпретация | хорошая у небольшого дерева | слабая |
| высокая размерность | терпимее | часто проблема |
| переобучение | глубокое дерево | слишком маленький `k` |

Нет победителя «вообще». Сравниваю на одной честной validation схеме.

## 18. Типичные ошибки

### Смотреть test при каждом эксперименте

Так test перестаёт быть независимым.

### Масштабировать до split/CV

```python
X_scaled = scaler.fit_transform(X)  # затем CV — leakage
```

Правильно — Pipeline.

### Верить train accuracy

Высокий train score может быть симптомом переобучения.

### Выбирать метрику без контекста

99% accuracy бесполезны, если положительный класс встречается в 1% случаев и модель всегда отвечает `0`.

### Считать дерево причинным объяснением

Правило дерева — predictive split в имеющихся данных, не доказательство причинности.

## 19. Как я должен мыслить при новой задаче

Допустим, дали dataset для определения дефолта клиента.

Я иду так:

1. Что означает одна строка?
2. Что такое target?
3. Когда должен формироваться prediction?
4. Нет ли признаков из будущего?
5. Как распределён target?
6. Какой Dummy baseline?
7. Какова цена FP/FN?
8. Какая validation схема честная?
9. Строю небольшое дерево как интерпретируемый baseline.
10. Для k-NN строю Pipeline со scaling.
11. Подбираю complexity только по CV.
12. Сравниваю не только mean score, но стабильность.
13. Один раз оцениваю победителя на test.
14. Разбираю ошибки.

## 20. Что должно остаться в памяти

```python
train_test_split(..., stratify=y, random_state=42)

DecisionTreeClassifier(max_depth=...)

Pipeline([
    ("scale", StandardScaler()),
    ("model", KNeighborsClassifier(n_neighbors=...)),
])

cross_val_score(...)
GridSearchCV(...)
```

Но важнее кода:

```text
не трогать test при подборе
preprocessing обучается только на train
сложность модели подбирается по validation
train score ≠ качество на новых данных
метрика следует из цены ошибки
```
