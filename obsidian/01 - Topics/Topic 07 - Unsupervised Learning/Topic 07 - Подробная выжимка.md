# Topic 07 — PCA и Clustering: подробная выжимка

[[ML Course]] · [[Topic 06 - Подробная выжимка]]

## 1. Главная идея

В supervised learning у меня есть `y`, поэтому можно проверить, насколько prediction близок к правильному ответу.

В unsupervised learning target нет.

```text
есть X
нет y
```

Поэтому алгоритм не «находит правильный ответ». Он показывает некоторую структуру данных **в рамках выбранных признаков, масштаба и метрики**.

Это принципиально важно: красивый кластер на графике ещё не означает реальный бизнес-сегмент.

## 2. Две задачи темы

### PCA

Уменьшить размерность, сохранив как можно больше общей вариативности данных.

### Clustering

Разделить объекты на группы по сходству без готовых labels.

Обе задачи зависят от геометрии пространства признаков.

## 3. Почему scaling снова важен

Пусть признаки:

```text
age: 18–80
annual_revenue: 10 000–10 000 000
```

Евклидова геометрия без scaling будет почти полностью определяться revenue.

Поэтому часто:

```python
from sklearn.preprocessing import StandardScaler

X_scaled = StandardScaler().fit_transform(X)
```

Для exploratory unsupervised анализа fit на выбранном dataset допустим, но если PCA является частью supervised CV pipeline, scaler и PCA должны обучаться внутри folds.

## 4. PCA — интуиция

Представим двумерное облако точек, вытянутое по диагонали.

Исходные оси `x1` и `x2` не совпадают с главным направлением облака.

PCA поворачивает систему координат так, чтобы:

```text
PC1 → направление максимальной variance
PC2 → максимальная оставшаяся variance, ортогональная PC1
```

В большей размерности идея та же.

## 5. Principal components

Каждая компонента — линейная комбинация исходных признаков:

```text
PC1 = a1*x1 + a2*x2 + ... + ap*xp
```

Коэффициенты называются loadings.

Компонента не обязана иметь простое человеческое значение. Иногда её можно интерпретировать по большим loadings, но нельзя автоматически назвать PC1 «богатством клиента» только потому, что туда сильно входят доход и расходы.

## 6. Explained variance

```python
from sklearn.decomposition import PCA

pca = PCA()
pca.fit(X_scaled)
pca.explained_variance_ratio_
```

Например:

```text
PC1  0.55
PC2  0.25
PC3  0.12
...
```

Первые две компоненты сохраняют 80% общей variance.

Но **variance ≠ predictive signal**. Target может зависеть от направления с маленькой variance.

Поэтому PCA перед supervised model — гипотеза, которую проверяю CV.

## 7. Выбор числа компонентов

Можно смотреть cumulative explained variance:

```python
np.cumsum(pca.explained_variance_ratio_)
```

Например выбрать минимальное число компонент, сохраняющее 90–95% variance.

Но это не универсальное правило. Иногда важнее compression ratio, latency или downstream model quality.

## 8. Reconstruction

После PCA можно приблизительно восстановить исходные данные:

```python
Z = pca.transform(X_scaled)
X_approx = pca.inverse_transform(Z)
```

Если оставить мало компонентов, часть информации теряется.

Полезная модель:

```text
исходные данные
↓ compress
несколько PC
↓ reconstruct
приближение исходных данных
```

## 9. Когда PCA полезен

- визуализация high-dimensional данных в 2D/3D;
- compression;
- коррелированные числовые признаки;
- ускорение некоторых моделей;
- снижение шума;
- подготовка пространства для некоторых distance-based методов.

Минус — теряется исходная интерпретируемость features.

## 10. k-means — интуиция

Нужно выбрать `k` центров.

Алгоритм повторяет:

```text
1. каждый объект → ближайший centroid
2. centroid → среднее объектов своего cluster
3. повторить до стабилизации
```

Цель — минимизировать сумму квадратов расстояний до центров (inertia).

```python
from sklearn.cluster import KMeans

km = KMeans(n_clusters=3, random_state=42, n_init="auto")
labels = km.fit_predict(X_scaled)
```

## 11. Какую геометрию любит k-means

Лучше всего:

- компактные кластеры;
- примерно сферические;
- похожие размеры/плотности;
- евклидово расстояние имеет смысл.

Плохо:

```text
два полумесяца
кольца
сильно разные density
много выбросов
```

k-means всё равно нарежет пространство, даже если естественных кластеров нет.

## 12. Initialization

Плохие начальные centroids могут привести к плохому локальному решению.

Поэтому используется несколько initialization (`n_init`) и k-means++.

Один запуск с одним случайным seed — слабое доказательство устойчивой структуры.

## 13. Inertia

```python
km.inertia_
```

Всегда уменьшается при увеличении `k`.

При `k = n_objects` inertia вообще станет нулём.

Поэтому нельзя просто выбирать `k` с минимальной inertia.

## 14. Elbow method

Строим:

```text
k → inertia
```

И ищем «локоть»: после какого `k` добавление новых кластеров даёт всё меньший выигрыш.

Это эвристика. Иногда локтя нет или несколько вариантов выглядят одинаково разумно.

## 15. Silhouette score

Для каждого объекта сравнивается:

- насколько он близок к своему cluster;
- насколько далеко от ближайшего другого cluster.

Значение:

```text
близко к 1 → хорошо отделён
около 0 → граница/пересечение
ниже 0 → возможно, объект ближе к чужому cluster
```

```python
from sklearn.metrics import silhouette_score

silhouette_score(X_scaled, labels)
```

Но высокий silhouette означает хорошую **геометрическую** структуру, не бизнес-ценность.

## 16. Profiling кластеров

После `labels` начинается самая важная аналитическая работа.

Возвращаю cluster id в исходную таблицу:

```python
df["cluster"] = labels

df.groupby("cluster")[numeric_cols].mean()
```

Смотрю:

- размер каждого cluster;
- медианы/распределения исходных признаков;
- категории;
- независимые бизнес-метрики;
- стабильность во времени.

Только после этого можно осторожно давать понятные названия сегментам.

## 17. Почему нельзя сразу назвать cluster «VIP»

Алгоритм знает только расстояния.

Он не знает:

- что такое VIP;
- ценен ли клиент;
- стабилен ли сегмент;
- можно ли воздействовать на него отдельной стратегией.

Название — интерпретация аналитика после profiling.

## 18. Stability

Очень важная проверка unsupervised результата.

Меняю:

- random seed;
- часть sample;
- scaling;
- небольшой набор features.

Если segmentation полностью разваливается, она слишком хрупкая для реального использования.

## 19. PCA + k-means

Иногда PCA перед clustering:

- убирает шум;
- уменьшает корреляции;
- ускоряет distance calculations.

Но может и удалить полезную локальную структуру.

Поэтому сравниваю:

```text
clustering на scaled original features
vs
clustering на PCA representation
```

и смотрю stability + usefulness.

## 20. Другие clustering методы

k-means — не универсальный алгоритм.

### Hierarchical clustering

Строит иерархию объединений/разделений. Полезна dendrogram для небольших datasets.

### DBSCAN

Ищет плотные области и умеет оставлять noise points. Может находить кластеры сложной формы, но чувствителен к scale и параметрам плотности.

Важно сначала понять форму задачи, а потом выбирать algorithm.

## 21. Unsupervised validation

Без target всё равно нужна проверка.

Возможные уровни:

1. **internal** — silhouette, inertia;
2. **stability** — seed/subsample/time;
3. **external** — связь с независимыми известными labels/метриками;
4. **business** — помогает ли segmentation принять полезное решение.

Последний уровень часто важнее красивой внутренней метрики.

## 22. Типичные ошибки

- PCA/k-means без scaling при несопоставимых единицах;
- считать PC1 реальным скрытым фактором без анализа loadings;
- считать explained variance predictive quality;
- выбирать `k` только по красивой картинке;
- считать cluster label готовым бизнес-сегментом;
- не проверять stability;
- игнорировать выбросы;
- использовать k-means для явно несферической структуры без сравнения альтернатив;
- считать отсутствие target разрешением не валидировать результат.

## 23. Как я решаю unsupervised задачу

1. Зачем вообще нужна сегментация/compression?
2. Какие признаки описывают нужное сходство?
3. Есть ли features, которые не должны участвовать?
4. Нужен ли scaling?
5. Есть ли выбросы?
6. Если PCA — сколько variance сохраняю и зачем?
7. Если clustering — почему выбран этот algorithm?
8. Как выбираю `k`/параметры?
9. Стабилен ли результат?
10. Как выглядят clusters в исходных features?
11. Есть ли внешняя/бизнес-проверка?
12. Что реально можно сделать с найденной структурой?

## 24. Минимум в памяти

```python
X_scaled = StandardScaler().fit_transform(X)

pca = PCA(n_components=2)
Z = pca.fit_transform(X_scaled)

km = KMeans(n_clusters=3, random_state=42, n_init="auto")
labels = km.fit_predict(X_scaled)

silhouette_score(X_scaled, labels)
```

И главное:

```text
PCA сохраняет variance
k-means минимизирует расстояния до centroids
ни то ни другое само по себе не знает бизнес-смысла
```
