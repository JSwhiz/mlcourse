# Topic 09 — Time Series: подробная выжимка

[[ML Course]] · [[Topic 08 - Подробная выжимка]]

## 1. Главная идея

Во временном ряду порядок наблюдений несёт информацию.

Для обычной табличной задачи строки часто можно перемешать. Для forecasting это может уничтожить смысл эксперимента.

Главный принцип:

> модель учится на прошлом и должна проверяться на будущем.

## 2. Сначала определить момент прогноза

Фраза «предсказать продажи» недостаточна.

Нужно ответить:

```text
Когда именно формируется прогноз?
Что известно в этот момент?
На какой горизонт нужен прогноз?
```

Например:

```text
каждый понедельник в 08:00
предсказываем суммарные продажи на следующие 7 дней
```

Теперь можно честно решить, какие признаки доступны.

## 3. Forecast horizon

Horizon — насколько далеко вперёд предсказываю.

```text
h=1   → следующий час/день
h=7   → неделя вперёд
h=30  → месяц вперёд
```

Модель, отличная на `h=1`, не обязана быть хорошей на `h=30`.

Поэтому horizon — часть постановки задачи, а не технический параметр после обучения.

## 4. Компоненты временного ряда

### Trend

Долгосрочное направление изменения уровня.

### Seasonality

Повторяющийся паттерн с известной периодичностью:

- часы суток;
- дни недели;
- месяцы;
- годовая сезонность.

### Autocorrelation

Связь текущего значения с прошлыми значениями того же ряда.

### Noise

То, что выбранная модель не может предсказать из доступной информации.

Реальный ряд часто является смесью всех этих компонентов.

## 5. Визуализация — первый шаг

До модели строю сам ряд:

```python
y.plot(figsize=(14, 4))
```

Смотрю:

- trend;
- скачки;
- смену режима;
- пропуски;
- периодичность;
- выбросы;
- изменение variance.

Среднее и стандартное отклонение без временного графика легко скрывают важную структуру.

## 6. Baseline обязателен

Forecasting особенно легко переусложнить.

Простейший baseline:

```text
y_hat[t] = y[t-1]
```

Это naive forecast: завтра будет как сегодня.

Если есть недельная сезонность:

```text
y_hat[t] = y[t-7]
```

Это seasonal naive.

Сложная модель полезна только если стабильно превосходит разумный baseline на будущих периодах.

## 7. Lag features

Чтобы превратить ряд в supervised dataset:

```python
df["lag_1"] = df["y"].shift(1)
df["lag_7"] = df["y"].shift(7)
df["lag_30"] = df["y"].shift(30)
```

Для строки времени `t` эти признаки содержат значения из прошлого.

После `shift` в начале появятся `NaN` — это нормально, прошлого ещё нет.

## 8. Rolling features

Например среднее последних 7 известных дней:

```python
df["rolling_mean_7"] = (
    df["y"]
      .shift(1)
      .rolling(7)
      .mean()
)
```

Почему сначала `shift(1)`?

Если написать:

```python
df["y"].rolling(7).mean()
```

rolling для момента `t` включает `y[t]`. Но именно `y[t]` я пытаюсь предсказать. Это target leakage.

Правильная мысленная проверка:

> Смог бы я посчитать этот feature за секунду ДО появления target?

## 9. Calendar features

```python
df["weekday"] = df.index.dayofweek
df["month"] = df.index.month
df["hour"] = df.index.hour
df["is_weekend"] = df["weekday"].isin([5, 6])
```

Календарные признаки известны заранее, поэтому обычно безопасны.

Но праздники, акции и внешние события нужно проверять по реальной доступности: был ли будущий promotion schedule известен в момент forecast?

## 10. Почему random split неверен

Плохо:

```python
train_test_split(X, y, shuffle=True)
```

Тогда train может содержать декабрь, а validation — октябрь того же года. Модель фактически учится на будущем относительно validation.

Это не имитирует production.

## 11. Chronological holdout

Простейшая честная схема:

```text
|----------- train -----------|--- test ---|
раньше                                позже
```

Например первые 80% времени — train, последние 20% — test.

Но один период может быть случайно лёгким/тяжёлым, поэтому лучше backtesting.

## 12. Expanding window

```text
fold 1: [train----][val]
fold 2: [train---------][val]
fold 3: [train--------------][val]
```

Train постепенно растёт, validation всегда находится позже.

В sklearn:

```python
from sklearn.model_selection import TimeSeriesSplit

cv = TimeSeriesSplit(n_splits=5)
```

## 13. Rolling window

Иногда очень старые данные уже не полезны.

Тогда train window имеет фиксированную длину:

```text
       [train][val]
            [train][val]
                 [train][val]
```

Это может лучше работать при сильном drift.

## 14. Expanding или rolling?

### Expanding

Подходит, если старые данные всё ещё полезны и хочется использовать максимум истории.

### Rolling

Подходит, если процесс заметно меняется и древние наблюдения вредят.

Выбор — гипотеза, которую нужно проверить backtesting.

## 15. Метрики

### MAE

```text
mean(|y - y_hat|)
```

Легко интерпретировать в единицах target.

### RMSE

Сильнее штрафует крупные ошибки.

### MAPE

```text
mean(|y-y_hat| / |y|)
```

Интуитивна как процент, но плохо ведёт себя около нуля.

Нет универсально лучшей метрики — она должна соответствовать стоимости ошибки.

## 16. Leakage во временных данных

Здесь leakage особенно коварен.

### Rolling без shift

Используется текущий target.

### Future aggregate

Например среднее продаж за весь месяц для прогноза дня внутри этого месяца.

### Неправильный encoding

Target encoding категории посчитан с использованием будущих наблюдений.

### Глобальный preprocessing

Scaler обучен на всей истории, включая будущий test period.

### Ретроспективно известный признак

Сегодня в dataset есть итоговый статус события, но в момент реального прогноза он ещё не был известен.

## 17. Autocorrelation

ACF помогает увидеть связь ряда с его лагами.

Высокая корреляция на `lag=7` может указывать на недельную сезонность.

Но autocorrelation сама по себе не гарантирует, что feature улучшит out-of-sample forecast. Это гипотеза для backtesting.

## 18. Multi-step forecasting

Если нужно предсказать 7 дней вперёд, есть разные стратегии.

### Recursive

Предсказываем `t+1`, затем используем прогноз как вход для `t+2`.

Минус — ошибки накапливаются.

### Direct

Отдельная модель для каждого horizon:

```text
model_h1
model_h2
...
model_h7
```

Дороже, но прогнозы не зависят рекурсивно друг от друга.

## 19. Prophet/ARIMA/ML — что выбирать

Название библиотеки вторично.

Сначала:

1. определить horizon;
2. построить naive baseline;
3. сделать честный backtesting;
4. понять trend/seasonality;
5. определить доступные regressors;
6. выбрать metric.

Только потом имеет смысл сравнивать ARIMA, Prophet, boosting по lag features и другие методы.

## 20. Residual analysis

После прогноза:

```text
residual = actual - forecast
```

Смотрю residuals во времени.

Если там остаётся явная сезонность или trend, модель не использовала часть доступной структуры.

Также важно искать периоды, где ошибка резко выросла: возможно, произошла смена режима.

## 21. Drift

Временные задачи почти всегда подвержены drift.

Поэтому недостаточно одной средней CV-метрики.

Смотрю score по folds:

```text
fold1: MAE 10
fold2: MAE 11
fold3: MAE 12
fold4: MAE 25  ← что произошло?
```

Последний fold может сигнализировать, что процесс изменился.

## 22. Что значит «честный feature»

Для каждой строки времени `t` мысленно ставлю стену:

```text
ПРОШЛО | момент prediction | БУДУЩЕЕ
```

Feature может использовать только информацию слева или заранее известную информацию справа (например календарь).

Если feature требует знания факта, который появится позже, это leakage.

## 23. Как я решаю forecasting-задачу

1. Определяю объект прогноза.
2. Фиксирую timestamp формирования prediction.
3. Фиксирую horizon.
4. Рисую target во времени.
5. Проверяю missing timestamps и выбросы.
6. Строю naive/seasonal baseline.
7. Создаю только доступные lag/rolling/calendar features.
8. Выбираю chronological CV.
9. Сравниваю модели на одинаковых folds.
10. Смотрю не только среднюю метрику, но и динамику по folds.
11. Анализирую residuals.
12. Проверяю drift.
13. Финально тестирую на самом позднем untouched периоде.

## 24. Типичные ошибки

- random split;
- rolling без `shift`;
- использование будущих агрегатов;
- отсутствие naive baseline;
- подбор параметров по последнему test period;
- считать MAPE хорошей при значениях около нуля;
- игнорировать horizon;
- оценивать только средний score;
- не учитывать задержку появления внешних признаков;
- считать красивую сезонность гарантией хорошего forecast.

## 25. Минимум в памяти

```python
df["lag_1"] = df["y"].shift(1)

df["roll_7"] = df["y"].shift(1).rolling(7).mean()

cv = TimeSeriesSplit(n_splits=5)
```

И главное:

```text
прошлое → train
будущее → validation/test
```
